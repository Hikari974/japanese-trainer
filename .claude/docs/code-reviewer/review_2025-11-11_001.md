#### M2: modalColor State Management (`training.tsx`, lines 94-95, 163)
**Location:** Lines 94-95, 128, 137, 163
```tsx
const [modalColor, setModalColor] = useState<ModalColor>(null);
// ...
// DO NOT reset modalColor here - it causes color flash during close animation
```

**Issue:** `modalColor` is never reset, relying on overwrite by next validation. While this works, it's implicit state management that could cause bugs if validation flow changes.

**Potential Edge Case:** If modal is opened without going through `handleValidate` (future refactoring), stale color persists.

**Recommendation:** Reset `modalColor` in `handleNext` after a short delay (e.g., 200ms) to clean up state:
```tsx
const handleNext = () => {
  setIsModalOpen(false);

  // Reset other state immediately...

  // Clean up modalColor after close animation completes
  setTimeout(() => setModalColor(null), 200);
};
```

#### L4: Missing Input Validation in normalizeRomaji (`training.tsx`, lines 53-61)
**Location:** Lines 53-61
```tsx
const normalizeRomaji = (text: string): string => {
  return text
    .toLowerCase()
    .trim()
    .replace(/si/g, 'shi')
    .replace(/ti/g, 'chi')
    .replace(/tu/g, 'tsu')
    .replace(/hu/g, 'fu');
};
```

**Issue:** No null/undefined check. Will throw if called with non-string.

**Recommendation:** Add guard:
```tsx
const normalizeRomaji = (text: string): string => {
  if (!text || typeof text !== 'string') return '';
  return text
    .toLowerCase()
    .trim()
    .replace(/si/g, 'shi')
    .replace(/ti/g, 'chi')
    .replace(/tu/g, 'tsu')
    .replace(/hu/g, 'fu');
};
```
