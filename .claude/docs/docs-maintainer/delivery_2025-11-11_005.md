## Features Completed

### 1. Complete Statistics System with AsyncStorage
**Files:**
- `app/types/statistics.ts` (NEW - 52 lines)
- `app/services/statistics.ts` (NEW - 178 lines)
- `app/hooks/useStatistics.ts` (NEW - 53 lines)

**Description:**
Implemented a complete statistics tracking system with offline-first persistence using AsyncStorage. The system tracks user performance per word-level-difficulty combination with composite keys.

**Architecture:**
- **Service + Hook Pattern:** Follows established preferences.ts pattern
- **Composite Keys:** `"${wordId}-${level}-${difficulty}"` for flat Record structure
- **Single Source of Truth:** Global stats calculated from words stats (no duplication)
- **Offline-First:** 100% local AsyncStorage, no backend required

**Scoring Logic (Simplified):**
```typescript
function calculatePoints(isCorrect: boolean, startCount: number, translationViewed: boolean): number {
  if (isCorrect && startCount === 1 && !translationViewed) {
    return 1; // Perfect attempt
  }
  return 0;
}
```

**Key Features:**
- 1 point per perfect attempt (correct answer + 1 reading + translation not viewed)
- Per-word statistics with attempts, correct count, perfect count, points
- Global statistics aggregated from all word stats
- Statistics by level (Kana, N5, N4, N3, N2, N1)
- AsyncStorage persistence with automatic save/load
- Error handling with graceful fallback to defaults

## Technical Decisions

### Decision 1: Composite Keys for Storage
**Choice:** `"${wordId}-${level}-${difficulty}"` composite keys
**Alternative:** Nested object structure
**Rationale:**
- Simpler to work with (flat Record)
- Easy to query specific word-level-difficulty
- Efficient for AsyncStorage serialization
- Extensible for future breakdown by difficulty

### Decision 2: Simplified Scoring (1 Point Per Perfect)
**Choice:** 1 point if (correct + 1 start + no translation viewed)
**Alternative:** Variable points by level/difficulty
**Rationale:**
- User requested simplification: "1 point à chaque fois"
- Clear boolean logic (easy to understand)
- Fair: rewards perfect attempts regardless of difficulty
- Simple to display: "+1" or nothing

### Decision 3: State Capture Timing
**Choice:** Snapshot state BEFORE recordAttempt()
**Alternative:** Pass state directly (would reset before capture)
**Rationale:**
- Prevents race condition with state resets
- Ensures accurate attempt data recording
- `handleNext()` resets state after recording completes

### Decision 4: MVP Scope for Stats Page
**Choice:** Simple global + level breakdown
**Alternative:** Complex charts, difficulty breakdown, trends
**Rationale:**
- User explicitly requested "Simple (MVP)"
- Faster implementation
- Clean, clear UI without overwhelming data
- Future-extensible architecture (can add complexity later)

### Decision 5: Translation Always Visible in Modal
**Choice:** Show translation in both success and failure modals
**Alternative:** Only show on failure
**Rationale:**
- User requested: "mettre la traduction dans le message de reussite ou d'echac feedback"
- Educational value: reinforces learning
- Consistent modal content regardless of result
