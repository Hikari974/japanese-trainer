#### File: `app/index.tsx` (MODIFIED - +63 lines)
**Purpose:** Home screen integration with unlock status and progression

**Changes:**

**1. Data Loading on Mount:**
```typescript
useEffect(() => {
  const loadLevelStates = async () => {
    setIsLoadingLevels(true);

    // Load unlock status
    const unlocked = await getUnlockedLevels();
    const unlockedSet = new Set(unlocked);
    setUnlockedLevels(unlockedSet);

    // Load progression for all levels
    const progressMap = new Map<JLPTLevel, LevelProgress>();
    for (const level of levels) {
      const progress = await calculateProgress(level);
      progressMap.set(level, progress);
    }
    setLevelProgress(progressMap);

    setIsLoadingLevels(false);
  };

  loadLevelStates();
}, []);
```

**2. Event Listener for Auto-Unlock:**
```typescript
useEffect(() => {
  // Refresh level states when unlock happens in training
  const unsubscribe = registerUnlockCallback(async () => {
    const unlocked = await getUnlockedLevels();
    setUnlockedLevels(new Set(unlocked));

    // Refresh progression
    const progressMap = new Map<JLPTLevel, LevelProgress>();
    for (const level of levels) {
      const progress = await calculateProgress(level);
      progressMap.set(level, progress);
    }
    setLevelProgress(progressMap);
  });

  return unsubscribe;
}, []);
```

**3. LevelButton Integration:**
```typescript
<LevelButton
  level={level}
  selected={selectedLevel === level}
  onPress={() => setSelectedLevel(level)}
  isLocked={!unlockedLevels.has(level)}
  progress={levelProgress.get(level) || null}
/>
```

## Technical Architecture

### UI State Flow

```
Home Screen Mount
      ↓
loadLevelStates() (async)
      ↓
getUnlockedLevels() → Set<JLPTLevel>
      ↓
calculateProgress(level) × 6 → Map<JLPTLevel, LevelProgress>
      ↓
setState: unlockedLevels, levelProgress
      ↓
Render 6 LevelButtons with props
      ↓
User interaction → Training session
      ↓
recordAttempt() triggers checkAndUnlockNextLevel()
      ↓
Unlock event emitted
      ↓
Home screen callback refreshes states
      ↓
UI updates automatically (real-time)
```

### Component Props Flow

```
index.tsx
  ↓
LevelButton (per level)
  ├─ level: JLPTLevel
  ├─ selected: boolean
  ├─ onPress: () => void
  ├─ isLocked: !unlockedLevels.has(level)
  └─ progress: levelProgress.get(level) || null
      ↓
ProgressBar (if unlocked && progress)
  ├─ progress: number (0-100)
  ├─ height: 8
  ├─ color: "$blue9"
  └─ backgroundColor: "$gray5"
```

## Technical Decisions

### 1. ProgressBar as Separate Component
**Decision:** Extract progress bar into reusable `ProgressBar.tsx` component.

**Rationale:**
- Reusability across app (stats page, skill trees, etc.)
- Single responsibility principle
- Easier to test in isolation
- Consistent progress visualization

**Trade-offs:**
- Pro: Clean API, reusable, testable
- Pro: Future-proof for other progress displays
- Con: Additional file (75 lines, minimal cost)

---

### 2. LevelButton Complete Refactor
**Decision:** Rewrite LevelButton instead of incremental changes.

**Rationale:**
- Original design didn't anticipate locked/progress states
- Complex conditional rendering cleaner with full rewrite
- Better prop API (isLocked, progress vs internal derivation)
- Easier to test all state combinations

**Trade-offs:**
- Pro: Cleaner code, better architecture
- Pro: 20 comprehensive tests (vs patching old tests)
- Con: More lines changed (88+ vs ~30 for patch)

---

### 3. Loading State on Mount
**Decision:** Show spinner during initial data load.

**Rationale:**
- Async operations (getUnlockedLevels, calculateProgress × 6)
- Prevents layout shift during data population
- Better UX than showing incorrect states then changing

**Trade-offs:**
- Pro: Clean UX, no flickering
- Pro: Prevents user interaction during loading
- Con: Slight delay on app launch (~100-200ms, acceptable)

---

### 4. Event Listener for Real-Time Updates
**Decision:** Subscribe to unlock events to refresh level states.

**Rationale:**
- Training session can unlock levels without user leaving
- Event-driven update feels responsive
- Leverages existing US-006.3 event system

**Trade-offs:**
- Pro: Real-time UI updates, no manual refresh needed
- Pro: Works seamlessly with fire-and-forget unlock pattern
- Con: Async state refresh in callback (properly handled with setState)

---

### 5. Fire-and-Forget Event Callback
**Decision:** Event callback doesn't await async operations.

**Rationale:**
- Event system fires callbacks synchronously
- Async operations (getUnlockedLevels, calculateProgress) don't block event
- setState handles async completion automatically

**Trade-offs:**
- Pro: No blocking in event emission
- Pro: React handles state update timing
- Con: Brief delay between unlock and UI update (50-100ms, imperceptible)
