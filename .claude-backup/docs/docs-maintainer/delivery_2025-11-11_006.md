### 2. Extended Romaji Normalization in Training
**File:** `app/training.tsx` (30 lines modified, +31/-2 = 29 net)

**Description:**
Enhanced romaji normalization to handle variant spellings found in the word database, ensuring flexible validation.

**Normalizations Added:**
1. **jy → j transformation:**
   - "jyoubu" → "joubu" (丈夫)
   - "jyugyou" → "jugyou" (授業)
   - Pattern: `jy` replaced with `j` globally

2. **chy → ch transformation:**
   - "chyawan" → "chawan" (茶碗)
   - "chyotto" → "chotto" (ちょっと)
   - Pattern: `chy` replaced with `ch` globally

3. **cchi → tchi transformation:**
   - "kocchi" → "kotchi" (こっち)
   - "macchi" → "matchi" (マッチ)
   - Pattern: `cchi` replaced with `tchi` globally
   - Rationale: User types "t" + "chi" for っち

4. **chu protection in hu→fu:**
   - Original: "hu" → "fu" (は行 romanization)
   - Problem: "chu" → "cfu" (breaks ちゅう)
   - Solution: Protect "chu" pattern before applying "hu" → "fu"
   - Implementation: Regex negative lookback `/(?<!c)hu/g`

**Combined Normalization Flow:**
```typescript
const normalizeRomaji = (romaji: string): string => {
  return romaji
    .toLowerCase()
    .trim()
    .replace(/jy/g, 'j')         // jyoubu → joubu
    .replace(/chy/g, 'ch')       // chyawan → chawan
    .replace(/cchi/g, 'tchi')    // kocchi → kotchi
    .replace(/shi/g, 'si')
    .replace(/tsu/g, 'tu')
    .replace(/chi/g, 'ti')
    .replace(/(?<!c)hu/g, 'fu')  // hu→fu, but protect chu
    .replace(/\s/g, '')          // remove spaces
    .replace(/,/g, '');          // remove commas
};
```

**Double Consonant Validation:**
- Pattern: `/([kstmgzdbp])\1/` detects double consonants
- Converts to single consonant + vowel pattern
- Example: "kk" in "poketto" → valid (ポケット)

## Technical Decisions

### Decision 1: Merge Dakuten + Handakuten Modes
**Choice:** Single "゛゜" mode combining 20 dakuten + 5 handakuten + 5 consonants
**Alternative:** Keep separate modes
**Rationale:**
- Simpler mode selection (4 modes instead of 5)
- Handakuten (pa/pi/pu/pe/po) rarely used alone
- Logical grouping: all voiced consonants together
- Frees space for Foreign mode button

### Decision 2: Add Foreign Katakana Mode
**Choice:** New "外" mode with 22 syllables (fa, fi, va, vi, etc.)
**Alternative:** Skip foreign syllables
**Rationale:**
- Required for modern loanwords (e.g., ファイル "file", ヴィオラ "viola")
- User explicitly requested: "ajouter syllabes katakana modernes pour mots étrangers"
- Complete coverage for JLPT vocabulary including loanwords
- Extensible for future word additions

### Decision 3: Double Consonants in Keyboard
**Choice:** Add k, s, t, m, g, z, d, b, p as separate buttons
**Alternative:** Auto-detect double consonants in input
**Rationale:**
- Explicit: User knows they're typing small tsu (っ)
- Consistent: Same button pattern for all double consonants
- Simple: No complex input detection logic
- Logical: Consonant in same row as its syllables

### Decision 4: Normalize in Code vs Correct Data
**Choice:** Hybrid approach (normalize variants, fix critical errors)
**Alternative A:** Pure normalization (keep data as-is)
**Alternative B:** Pure data correction (remove all normalizations)
**Rationale:**
- Variants (jy/chy) are common romanization alternatives → normalize
- Critical errors (hiragana in romaji) are data entry mistakes → must fix
- Hybrid balances flexibility and data quality
- Code normalization handles user input variations
- Data correction ensures database integrity

### Decision 5: っち Pattern as "tchi"
**Choice:** Normalize "cchi" → "tchi" (user types "t"+"chi")
**Alternative:** Accept "cchi" as valid (Hepburn romanization)
**Rationale:**
- Consistent with keyboard design (explicit consonant buttons)
- Clear for learners: "t" button = small tsu (っ)
- Avoids adding special "cchi" syllable button
- Can be relaxed later if user requests "cchi" acceptance
