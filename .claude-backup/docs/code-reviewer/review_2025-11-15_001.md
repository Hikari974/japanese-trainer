## Medium Priority Issues

### 1. [PERFORMANCE] Optimisation possible du calcul de progression

**File:** `app/services/statistics.ts:291-332` (fonction `calculateLevelProgress`)

**Issue:**
La fonction `calculateLevelProgress` charge les statistiques completes depuis AsyncStorage puis itere sur tous les word IDs disponibles. Si le nombre de mots devient tres important (ex: plusieurs milliers), cette approche pourrait devenir lente.

**Current code:**
```typescript
export async function calculateLevelProgress(level: JLPTLevel): Promise<LevelProgress> {
  try {
    const stats = await loadStatistics(); // Charge TOUT
    const availableWordIds = getAvailableWordIdsForLevel(level);
    const totalWords = availableWordIds.length;

    let masteredWords = 0;
    for (const wordId of availableWordIds) {
      const totalPoints = getTotalPointsForWord(wordId, level, stats);
      if (totalPoints >= 5) {
        masteredWords++;
      }
    }
    // ...
```

**Impact:**
- Performance acceptable actuellement (300 mots max pour N1/N2)
- Pourrait devenir problematique si dataset s'agrandit significativement
- Chaque appel recharge tout depuis AsyncStorage

**Recommendation:**
Pour l'instant, **ACCEPTABLE** car:
1. Dataset limite (300 mots max)
2. AsyncStorage est rapide pour petites donnees
3. Calcul simple (pas de traitement lourd)

Si performance devient probleme a l'avenir, envisager:
- Cache en memoire des statistiques dans `useStatistics` hook
- Calcul incremental (update progress lors de recordAttempt)
- Index pre-calcule des mots maitrises

**Severity:** Medium (nice-to-have, pas urgent)
